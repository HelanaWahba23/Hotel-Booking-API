# الأدوار والصلاحيات

يعتمد المشروع على Role-Based Access Control. تعريف السياسات موجود مركزيًا في:

`HotelBooking.Api/Security/AuthorizationPolicies.cs`

## مصفوفة الوصول

| المستخدم | صلاحيات الـAPI الأساسية | الممنوع |
|---|---|---|
| العميل Customer | إنشاء الحجز، عرض حجوزاته، إلغاء الحجز قبل تأكيده، وكتابة تقييم بعد الإقامة | لا يرى حجوزات العملاء الآخرين أو عمليات الإدارة |
| الموظف Staff | إنشاء الحجز، عرض الحجوزات، تحديث الحالة والدفع، والإلغاء | لا يعدل الأسعار أو الخصومات أو الأدوار |
| المدير Manager | التقارير، الغرف والأسعار والسعة، بيانات الفندق، المستخدمون، والتقييمات | لا يمنح دور Admin ولا يزيله |
| مدير النظام Admin | جميع عمليات المدير وإدارة أدوار المستخدمين | محمي من إزالة آخر حساب Admin |

## سياسات الـAPI

- `CustomerOnly`: عمليات الحجز والتقييم الخاصة بالعميل.
- `CanCreateBooking`: إنشاء الحجز للعميل أو موظف الاستقبال.
- `CanManageBooking`: العميل يلغي حجزه وهو Pending فقط، وفريق الفندق يلغي Pending أو Confirmed.
- `FrontDesk`: التشغيل اليومي للحجوزات والمدفوعات للموظف والمدير وAdmin.
- `Management`: التقارير وإدارة الفندق للمدير وAdmin.
- `AdminOnly`: تغيير أدوار المستخدمين والعمليات التقنية الحساسة.

## حسابات التطوير

| الدور | البريد | كلمة المرور |
|---|---|---|
| Staff | `staff@hotel.com` | `Staff@123` |
| Manager | `manager@hotel.com` | `Manager@123` |
| Admin | `admin@hotel.com` | `Admin@123` |

هذه الحسابات للعرض والتطوير فقط، ويجب تغييرها قبل نشر نسخة العميل.
