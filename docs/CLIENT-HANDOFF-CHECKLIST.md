# Client handoff checklist

استخدم القائمة التالية قبل تسليم نسخة النظام لأي فندق:

- [ ] تغيير اسم الفندق والوصف والعنوان وبيانات التواصل والعملة والضريبة.
- [ ] إدخال أنواع الغرف والغرف والأسعار والمرافق والصور الحقيقية.
- [ ] ضبط سياسة الإلغاء ومواعيد Check-in وCheck-out.
- [ ] إنشاء بيانات Admin خاصة بالعميل وحذف أي حسابات عرض.
- [ ] توليد JWT secret عشوائي قوي وعدم وضعه داخل Git.
- [ ] استخدام كلمة مرور قوية ومستقلة لقاعدة البيانات.
- [ ] تحديد دومين الـFrontend فقط داخل CORS.
- [ ] تعطيل Swagger في الإنتاج أو حمايته إذا لم يحتج إليه العميل.
- [ ] ربط بوابة الدفع الحقيقية وتأكيد الدفع من Webhook موثوق، وليس من تطبيق العميل.
- [ ] ربط مزود البريد أو WhatsApp لإشعارات الحجز والإلغاء.
- [ ] تفعيل HTTPS وشهادة SSL.
- [ ] إعداد نسخ احتياطي يومي لقاعدة البيانات وتجربة الاستعادة.
- [ ] إعداد مراقبة للأخطاء واستهلاك الخادم والتنبيه عند توقف `/api/health`.
- [ ] نشر سياسة الخصوصية وشروط الاستخدام وسياسة الإلغاء الخاصة بالفندق.
- [ ] تنفيذ اختبار قبول مع العميل قبل فتح الحجز للجمهور.

## عناصر التسليم المقترحة

- Source code وملف إعدادات الأسرار بدون القيم السرية.
- رابط Swagger أو وثيقة API.
- بيانات دخول الإدارة تُرسل عبر قناة آمنة.
- نسخة احتياطية أولية من قاعدة البيانات.
- دليل تشغيل واستعادة مختصر.
- اتفاق صيانة يحدد الاستضافة والنسخ الاحتياطية والدعم والتحديثات.
